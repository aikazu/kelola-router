# Flow Gaps Remediation — Master Plan

> **For agentic workers:** This master index points to five phase plans. Each phase is a self-contained, working, testable deliverable. Phases can be executed sequentially or in priority order (security → proxy → reliability → UI). Sub-skill: `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`.

**Goal:** Remediate 60 flow gaps identified in the 2026-06-02 backend + UI/UX audit, split across five phase plans so each plan stays small and independently shippable.

**Architecture:** Strict TDD per task. Each task is a red-green-refactor cycle with a commit. No batch refactors. Test files live next to source (`src/**/*.test.ts` for unit, `tests/integration/*.test.ts` for proxy) — both already established in the repo.

**Tech Stack:** Hono, better-sqlite3, Preact + @tanstack/react-query, vitest, supertest-style fetch in tests, scrypt for passwords, ulid for IDs.

**Source audits:**
- Backend: 30 findings (5 critical, 11 high, 9 medium, 5 low)
- UI/UX: 30 findings (8 critical, 10 high, 8 medium, 4 low)
- Verification spot-checks: `/v1/models` route, `parseError` defined-never-called, `applyErrorState` defined-never-called, CSRF gap on `/api/admin/*`, `transport` setting dead config, pipeWithUsage has no AbortController, `/api/login` has no rate limit, Login.tsx uses `alert` + `location.reload` — all confirmed against source on 2026-06-02.

## Execution Order

Run in this order. Each phase leaves the system green and deployable:

1. **Phase 1 (security)** — MUST be first. Closes remote-exploit gaps before anything else.
2. **Phase 2 (proxy pipeline)** — Core path stability. Affects every production request.
3. **Phase 3 (backend reliability)** — Operational hygiene. Required for stable long-running deploys.
4. **Phase 4 (UI login + a11y)** — User-facing criticals. Login is the door.
5. **Phase 5 (UI navigation + forms)** — UX polish. Safe to defer if time-constrained.

## Cross-Phase Conventions

- **Test location:** `src/**/*.test.ts` colocated with source for unit; `tests/integration/` for cross-module. Match existing pattern from CLAUDE.md.
- **DB isolation in tests:** Use `process.env.ROUTER_DB_PATH = join(mkdtempSync(...), "t.db")` in `beforeEach`. Call `resetDb()` from `src/server.ts` between cases. Call `clearCache()` from `src/db/repos/settings.ts` when mutating settings mid-test.
- **CSRF in tests:** Integration tests for `/admin/*` POSTs must set `Origin` matching `Host` or omit `Origin` entirely.
- **Commit style:** Conventional commits, ≤300 LOC per commit. Branch per phase recommended (`fix/phase-1-security`).
- **No `any`**, `const` over `let`, early returns. TypeScript strict mode.
- **Indonesian** for user-facing strings, **English** for code/comments/logs.

## Out of Scope (Documented but Deferred)

The following findings are tracked in the audit but NOT included in these plans because they are either low-impact, require design discussion, or conflict with in-flight work:

- Backend LOW: `setModelLock` negative-cooldown guard, `deleteAccount` cascade signal, `getClientKeyByKey` last_used, `aggregateUsage` unique client count, quota retention docs, sessions last_seen throttle, `truncateSseEvents` dead code (delete or wire), `selection.ts` sort stability.
- UI LOW: confirm queue race, sticky Map wiring decision (covered in phase 2 as removal), unknown-route 404 page (covered in phase 5), `min-width` mobile table.
- Design decisions required before implementation:
  - **Sticky mode:** keep and wire, or remove entirely? Phase 2 plan defaults to removal but flags the decision.
  - **`x-admin-key` bypass when password set:** keep for scripts (current) or gate behind flag? Phase 1 keeps current behavior and adds explicit warning in docs only.
  - **Persisted rate-limit buckets:** in-memory (current) or DB-backed? Phase 1 keeps in-memory and adds restart warning.

These are intentionally not plan-frozen; revisit after phases 1-3 ship.
